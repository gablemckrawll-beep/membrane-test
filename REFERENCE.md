# Разбор главной johwska.com

Проверено 14 октября 2026 года по работающей странице, DOM и публичному JavaScript-бандлу. Это технический разбор; реализация эффекта пока не создана.

## Главный вывод

Видимая поверхность — отдельная глянцевая эластичная мембрана. Трёхмерная модель головы используется как невидимая форма, которая продавливает мембрану. Курсор поворачивает форму, а симуляция переносит её движение на поверхность. Простого поворота GLB с металлическим материалом для воспроизведения эффекта недостаточно.

## Подтверждённый стек

- React 17.0.2, Chakra UI и Emotion для интерфейса.
- Inertia для навигации и передачи данных страницы.
- Three.js напрямую, собственный класс на основе WebGLRenderer; React Three Fiber в исследованном коде не обнаружен.
- GLTFLoader загружает модель головы.
- PMREMGenerator преобразует панорамную JPEG-карту окружения для отражений.
- Собственные GLSL-шейдеры и float/half-float render targets для расчёта мембраны.
- requestAnimationFrame обновляет сцену; react-spring участвует в анимации интерфейса.

CMS по одному клиентскому бандлу достоверно не установлена. Она не определяет визуальный эффект главной.

## Как устроен кадр

1. Координаты мыши или касания переводятся в диапазон −1…1.
2. Голова плавно поворачивается к целевой точке через quaternion.rotateTowards. Коэффициент затухания rotationDecay = 0.002 учитывает время кадра.
3. Голова рендерится ортографической камерой в отдельную текстуру. Несмотря на имя depthMap, RGB содержит мировые координаты XYZ, а alpha — наличие поверхности. Это не обычный depth buffer.
4. Шейдер сил сравнивает положение мембраны с формой головы. Он добавляет давление при пересечении, движение формы в зоне контакта, возврат поверхности к исходному состоянию и локальное «дыхание» около носа.
5. Положения точек обновляются в двух попеременно используемых render targets — ping-pong. Затем шейдер ограничений корректирует расстояния между соседями, контакт с головой и края мембраны.
6. Vertex shader видимой сетки читает XYZ из текстуры симуляции. Нормали рассчитываются по четырём соседним точкам, поэтому блики соответствуют новой форме.
7. Мембрана рендерится перспективной камерой с модифицированным MeshPhysicalMaterial, отражениями окружения и освещением.

Исследованный код не выводит модель головы отдельным видимым проходом: итоговая сцена содержит мембрану и свет.

В конфигурации присутствует stiffness = 625, но соответствующие пружинные силы в исследованном шейдере закомментированы. Натяжение обеспечивается активными проходами ограничений. Передавать stiffness как действующий регулятор без изменения шейдера нельзя.

На одно обновление приходится 51 проход симуляции: один расчёт сил и 3 × (один проход применения сил + 16 проходов ограничений). Дополнительно выполняются проход формы головы и финальный рендер. Поэтому производительность нужно проверять на целевых устройствах.

## Почему выглядит именно так

- Мембрана сглаживает мелкие детали головы, сохраняя нос, глаза, губы и общий силуэт.
- Карта окружения и clearcoat создают влажные блики и цветные отражения.
- Контакт движущейся формы тянет поверхность, создавая складки и ощущение вязкости.
- Дыхание — отдельная периодическая сила около носа, а не морф-анимация самой модели.
- Мягкость эффекта объясняется геометрией мембраны; отдельный blur/bloom-проход в исследованном рендере не найден.

## Архитектура для нашего проекта

Предлагаемая структура, ещё не реализованная:

```text
src/
  main.ts
  hero/
    HeroScene.ts            # камеры, сцены, цикл кадра
    ModelContactPass.ts     # мировые XYZ модели + маска
    MembraneSimulation.ts   # GPU-текстуры, силы, ограничения
    MembraneMaterial.ts     # геометрия и физический материал
    PointerController.ts    # курсор/касание, плавный поворот
    shaders/
      contact.vert.glsl
      contact.frag.glsl
      forces.frag.glsl
      integrate.frag.glsl
      constraints.frag.glsl
public/
  models/head.glb
  environments/studio.jpg
  fallback/hero.webp
```

Для самостоятельного прототипа достаточно Vite + TypeScript + Three.js. Если основной проект использует React, сцену можно подключить через один компонент с canvas и очисткой ресурсов при размонтировании; расчёт симуляции следует оставить внутри Three.js.

Порядок реализации:

1. Собственная GLB-модель, камера, кадрирование и карта окружения.
2. Проход мировых координат формы и статическая мембрана.
3. GPU-расчёт контакта и ограничений, проверка устойчивости.
4. Плавный поворот головы, движение мембраны и дыхание.
5. Настройка бликов и цвета, адаптация к мобильным экранам.
6. Проверка FPS, понижение качества на слабых устройствах, остановка в скрытой вкладке, статичный режим для reduced motion и отсутствия поддержки нужных GPU-буферов.

В оригинале предусмотрены half-float буферы для iOS и проверка GPU-расширений. В новом проекте следует добавить явный визуальный fallback. При переходе на актуальную Three.js нельзя переносить старые shader chunks и настройки цветового пространства буквально: материал нужно адаптировать к выбранной версии.

Для близкого результата особенно важны форма собственной модели, положение камеры и карта отражений. Сначала следует воспроизвести геометрию и контакт, затем подбирать материал. Числа выше — стартовые ориентиры, зависящие от масштаба сцены.
